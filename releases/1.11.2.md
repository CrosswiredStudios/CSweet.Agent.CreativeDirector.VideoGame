# 1.11.2

## Clearer production decisions and faithful engine selection

- Ask for the project's visual/audio asset approach in plain language. The exact strategy remains in structured decision data instead of being pasted as JSON into the question or rationale.
- Record an explicit Phaser or Babylon.js preference, including a request for the latest Phaser, in durable project preferences and scoped memory. A pitch that omits or substitutes the chosen engine, or pins a Phaser version despite a latest-version request, gets one automatic correction attempt and is not submitted if still contradictory.
- Treat phrases such as "no 3D" as exclusions when selecting a toolchain recipe. An explicit manager engine choice takes priority over incidental pitch wording.
- Wait for Technical Director staffing before raising a build-capacity decision. If managed build capacity is still missing, explain it as an automated build-runner prerequisite without suggesting an engine change or blocking independent planning.
- No new capabilities, credentials, configuration fields, or network access are requested.

Updating this agent does not install or certify a build runner. For automated Phaser builds, a compatible Node/TypeScript toolchain installation and certified Office image must still be made available through the normal setup process. Existing decisions are not rewritten; use a fresh business or a newly reviewed project direction to exercise this flow from the beginning.
