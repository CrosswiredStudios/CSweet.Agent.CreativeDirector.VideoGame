# 4.1.2

Production-brief reviews no longer fail over bookkeeping the agent can derive itself.

- The model supplies the judgment: checklist evidence, issues, findings and whether the Director must resolve a scope or
  authority question. The agent derives each check's status from its open issues, the required changes from the open
  blocking issues (exact `change` text, in order) and the disposition (open blockers: changes required, or escalate when
  flagged; none: accepted). An open blocking issue outweighs an `accepted` label.
- Still rejected, because code cannot settle them: missing, repeated or unknown checks; incomplete issues; a check marked
  blocking with no blocking issue; an escalation with no blocking question; an earlier blocker that was dropped, moved,
  reworded or downgraded.
- The review is requested with a JSON schema (`creative_review`). A rejected response goes back to the same conversation
  with the exact reason and the model's previous answer, up to two corrections per turn, so the review is repaired rather
  than redone. The correction requests are visible on the agent's recorded model calls.
- After the corrections are used up, the turn still returns exactly "Creative review did not return actionable, consistent
  findings.", which Director 0.6.x retries on. No Director change is needed.

Why: on 2026-11-11 QFN Games' production brief stalled after three rejected reviews. Each was substantive; one accepted
the brief. They failed only because a check carrying advisory issues was marked passed, or the required changes were
paraphrased. Tests replay the structure of those three responses.
